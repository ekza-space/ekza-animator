## What moved lazy

1. **Lint rule descriptions** (`io`, M-AI-B5-4). The built-in export profiles are eager and built their rule lists from
   `LINT_RULES`, so every rule description rode the first visit. `lint/severities.ts` now holds the ids and severities
   (`LINT_SEVERITIES`, `ruleSeverity`, `profileRules`, `VRM_RULE_IDS`); `rules.ts` composes `LINT_RULES` with the
   descriptions in the same order (checked equal to the old table). `lintExport`, `meshes`, `bakeIntoModel` and the
   profiles import `severities.ts`.
2. **The actor side of the run scope** (M-AI-B5-2; MCP-SPEC §4.10, P1's explicit-target reading). `operators/scope.ts`
   and `operators/builtin/scoped.ts` keep only dispatchers: a user run calls the shipped `workflows/targets` rules
   (`selectedKeys`, `selectedKeyIds`, `selectedControls`, `targetCurves`, `activeClipRecord`, `pollClipEdit`), which
   are what P1's user paths computed; an agent run calls `operators/actorScope.ts` (scope selection, character and
   clip, targets, the empty-scope poll, and the agent checks of `key.tween`, `graph.curves.simplify`,
   `rig.ikFk.matchRange`, `pose.mirrorAnimation` and `key.convert`). `actorScope.ts` is part of the `actorRun.ts`
   chunk (`export * as ACTOR_SCOPE`); `loadActorKit` (moved from the runner into `scope.ts`) installs it.
   Who loads it before an actor poll: the runner (before the first poll of an actor run, as before), `loadAgentOperators`
   (now loads the operators and the kit together; the agent runtime calls it when it attaches), `createHeadlessEditorApp`
   (installs it synchronously, as it registers the agent operators up front), and the tool layer's `run` awaits
   `loadAgentOperators` before its scope probe (`operators.poll` with the actor). An actor context that reaches the
   helpers before the kit loaded throws `unavailable`; no caller does.
3. **Lazy operator bodies** (M-AI-B5-3; independent of M-AI). `operators/builtin/lazyBodies.ts`: an operator file keeps
   its definitions and polls eager and its apply bodies become a chunk loaded by each run's `prepare` — the pattern
   `pose.mirrorAnimation` already used (§5.27), except that the loader returns the module itself once loaded, so every
   later run stays synchronous up to `apply` exactly as before. Applied to:
   - `graph.ts` → `graphBodies.ts`: all 17 `graph.*` bodies with their helpers (tangent targets, handle fields,
     ripple scope, Euler filter, Simplify, paste insert).
   - `pose.ts` → `poseBodies.ts`: `pose.resetToRest`, `copy`, `paste`, `mirror`, `pinFeet`, `plantFeet`
     (`pose.unpinFeet` is one `setState` and stays). `pose.paste`'s prepare loads the bodies, then reads the copied
     pose as before (session clipboard, else the system clipboard).
   - `clip.ts` → `clipBodies.ts`: `clip.new`, `duplicate`, `delete`, `setSettings`, whose `prepare` was already
     asynchronous (it opens partitions); `clip.rename` and `clip.setActive` stay eager.
   The bodies moved unchanged (generated by moving the `apply` blocks, then imports trimmed). Model, clip and project
   imports prefetch every body chunk (`file.ts` `loadImport`, `file.openProject`; `preloadOperatorBodies`), the intent
   rule of §5.21.2: a character is about to arrive. Without a prior import (a recovered autosave), the first graph or
   pose run of the session waits for one small chunk.
4. **check:size boundaries** (M-AI-B5-6): `actor-scope`, `graph-bodies`, `pose-bodies`, `clip-bodies`, each with a
   string only its chunk contains, so a later eager import fails the gate.

## Kept eager (M-AI-B5-5)

- Presence registry (`presence/registry.ts`, 0.5 kB): `app.presence.upsert` is synchronous and the agent runtime may
  upsert before a lazy load resolves; a lean rewrite saves ≈ 0.15 kB only.
- The runner's rule branches (control flow on `actor` in `run`), `agentChunk.ts` (the ids `lazyOperatorChunk` needs),
  `agentBase.ts` (`framesProblem` serves the user-visible `key.tween {frames}`).

  history, without the kit.
- The doc store's restore host (`MemoryDocumentStore.restoreHost`, `[RESTORE_HOST]`): a method over the store's
  private state.
- The status pill (`shell/StatusLine.tsx`) and the Agent panel's lazy registration (`panels/agent/`): B3's files; the
  panel could use the existing `lazyPanelDef` helper (≈ 0.2 kB) when B3 owns it.

The later steps were already lazy: ②–⑤ load through `stepView`/`stepEnter` (`MarkersStep`, `RigStep` with the

## Behaviour

No contract changed. User runs read and write exactly what they did (the dispatchers call the same `targets` rules P1's
user paths duplicated); agent runs are unchanged (the agent-tools suites, the `editor-core/test/agent` suites and
`ai-00-foundation` pass). Timing: the first run of a graph or pose operator without a prior import awaits its chunk;
`pose.paste` loads its bodies before reading the clipboard.
