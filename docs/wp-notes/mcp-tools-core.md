## Decisions and deviations (INT copies them to DECISIONS-OPEN §H as MAI-P2-n)

- **MAI-P2-1** `AGENT_TOOLSET_VERSION` is `1.0.0-dev.1`: one bump for P2's whole change set over D0's empty `1.0.0`
  manifest (the D0 note MAI-D0-12 asks every manifest change to bump; a pre-release series avoids counting down; INT
  picks the release version). While iterating inside the branch the manifest was regenerated by deleting the file
  first (the update guard compares against the committed file); the merge-base guard (no manifest on `dev`) passes.
- **MAI-P2-2** `biome.json` leaves `packages/agent-tools/tools.manifest.json` out (one `files.includes` line): the
  committed manifest must stay byte-identical to the generator's output, and biome folds its short arrays. Root
  config file: INT reviews.
- **MAI-P2-3** D0 literals that asserted "no tool is ready" now follow the manifest (literal updates, §3 rule 10):
  `agent-tools/test/runtime.test.ts` (the catalogue serves its ready tools; the grant test stubs the catalogue runs
  so it still checks the gate alone) and `mcp-server/test/{in-process,cli}.test.ts` (tools/list equals the committed
  manifest's names; prompts/list equals the prompts with plans; an unknown tool is still a protocol error). P6 owns
  those files.
- **MAI-P2-4** Labels carry the intent only where the operator takes a `label` argument (the ten M-AI operators).
  Shipped operators that tools run — `clip.new`, `clip.duplicate`, `clip.rename`, `clip.setSettings`,
  `clip.setActive`, `clip.delete`, `key.tween`, `graph.tangent.*`, `graph.keys.setFields`, `graph.curve.setWeighted`,
  `graph.infinity.set`, `graph.eulerFilter`, `graph.curves.simplify` — have none, so their steps read
  `AI: <operator label>`. Hand-off to P1/INT: an optional `label` (set by the tool layer only) on those operators
  makes `intent` show (§5.6); the tools then pass it.
- **MAI-P2-5** `pose_reset` runs `key.write` with the rest values (several frames in one step) instead of
  `pose.setAt` (one frame per run); locked channels and `keyAll: false` attributes (ikFk, soft) are left out by the
  tool.
- **MAI-P2-6** Arguments P2 hands to `pose.goals` (P1 to confirm): `aims[].bone` is the humanoid name (else the node
  name), `direction` a unit vector in character space, `split` only on head aims (default neck 0.4, head 0.6);
  `ik[].position` the end bone's target position, `ik[].rotation` the end bone's world rotation (its rest rotation
  turned by the named angles), `ik[].pole` the **pole control's position** (the mid joint plus `poleDirection` ×
  max(upper length, 0.1 m)).
- **MAI-P2-7** `pose_aim` turns a bone's own axis (from the joint toward its first child, §4.10). A head's axis runs
  up from the neck, so a head is turned with `pose_set` on its twist channel (axis hints say "twist", the sign checked
  with `pose_read` orientDeg); the description and the recipes guide say so. P2's AE-12 script does exactly that.
- **MAI-P2-8** `rig_describe` concise (§5.5, ≤ 1,500 tokens on Seed-san): lists the primary controls, counts
  secondary and finger controls per body part and the controls a limb's current mode hides in the editor
  (`leg.L fk (hidden in IK)`) in `secondary`, and leaves attribute details out (their `@channels` are listed);
  `bodyParts` or `detail: 'detailed'` list everything. `pose_read`'s default targets are the same concise list (one
  folding rule, `conciseFolding`), so its default read fits 1,500 tokens on Seed-san.
- **MAI-P2-9** `pose_set` no-op rule (§6.2 "pose_read fed back is a no-op"): a value equal (within half an output
  rounding step) to the keyed value is left out only when the channel already has a key at that frame; every other
  edit keys, equal values included, so blocking a rest pose at f0 keeps it when f10 is keyed (§11.3 blocker). Fed back
  at a keyed frame: no step; elsewhere the motion stays identical.
- **MAI-P2-10** Stale check: a clip this actor never saw has no automatic check (the first write passes); every
  result that names a clip marks it seen (scene_summary marks every clip it lists); the actor's own batches are found
  after the run by the recorded step's `docTxId` (`markOwn`), its undo navigations by `runOwn`; a document load
  clears the memory; a foreign change older than the 1,024 remembered batches answers with a warning only.
- **MAI-P2-11** `OperatorRun.warnings` (toasts raised during a run) come from wrapping `services.notify.toast` for the
  duration of the run (warning, error and info toasts; the user still sees them). A frozen notifier is left alone.
- **MAI-P2-12** The redo wait (§5.8 4a) applies with the `user` capability; a host that cannot confirm answers
  `redo_pending` at once; dry runs skip it. Its card resolves when the user's redo stack holds no user step.
- **MAI-P2-13** Confirmations: `tool.confirm` returns null when nothing is consequential; without the `confirm`
  capability the call needs `confirm: true` (`confirm_required` otherwise). `pose_ik_target` (no `confirm` argument)
  confirms only on hosts that can ask. `clip_update` changing fps needs `confirm: true` headless too (§5.9 "headless:
  consequential calls need confirm: true").
- **MAI-P2-14** Pause: a call that waited in the queue meets a pause that came meanwhile (`paused`, "holds nothing");
  the running call finishes.
- **MAI-P2-15** Deadlines stay the host's (it aborts the call's signal); the runtime reports the waits as progress
  messages `WAITING_FOR_DRAG`, `WAITING_FOR_CONFIRM` and `WAITING_FOR_REDO` (exported) so the bridge can extend a
  deadline once when a card opens (§5.8 7). Wait messages bypass the 250 ms progress throttle.
- **MAI-P2-16** Presence: at the start of every live call the activity is the tool's title; tools refine it with
  `ctx.focus` (targets, frame, label); 3 s after the call the focus and activity are cleared (the peer stays; P7
  removes it at disconnect).
- **MAI-P2-17** `clip_update {activate: true}` headless runs `clip.setActive` with `access: 'view'` (no user to
  protect); live it needs View (unchanged).
- **MAI-P2-18** `history_revert`: `unreachable` lists this runtime's own step ids found in neither stack (the runtime
  remembers its last 5,000 step ids); `includeUserSteps` works with `to` only. Checkpoints (≤ 200) and cursors (≤ 64)
  live in the runtime (`runtimeStateOf`).
- **MAI-P2-19** `keys_adjust` attribute offsets: the operator takes one number for every attribute, so angle
  attributes take `offsetDeg`, distance attributes `offsetM`; both kinds with offsets in one call → `invalid_args`
  "split the call".
- **MAI-P2-20** `keys_tween` passes `amountPercent` as the operator's amount; beyond ±100 % it warns unless the user's
  Tween overshoot preference is on (the shipped operator clamps).
- **MAI-P2-21** `wrap` on a non-loop clip → `invalid_args` at `wrap` (§6.4 "loop clips only"); `rig_describe` and the
  goal tools answer `busy` while the character is still loading.
- **MAI-P2-22** Examples (MAI-D0-25 hand-off): every catalogue tool has a minimal `example`, including the other
  packages' definitions (additive `example` lines only, not in the manifest).

## Gated on P1 — merge P1 before P2 (§10.1 order)

The tools are ready in the manifest (the contract), but some run P1's work:

- **Hazard before P1:** `keys_tween`, `curves_set_interpolation`, `curves_euler_filter` and `curves_simplify` (not
  dry) run scope-ready operators. Until P1 migrates them to `selectionOf(ctx)`/`scopedClipOf(ctx)`, the shipped
  operators read the **user's** selection and active clip under an actor. Their tests are
  `describe.skipIf(!READY.p1)`; if P2 ever merged first, these four must not be called.
- Live `clip_create` without `activate` and `clip_delete` of the user's active clip need P1's `clip.new {activate}`
  and actor-safe `clip.delete`; until then the runner's invariant fails them (`internal`, rolled back).
- `key.write`, `key.delete`, `key.adjust`, `key.retime`, `pose.setAt`, `pose.goals`, `pose.transfer`,
  `clip.makeLoop`, `edit.revertSteps` are D0 stubs: the tools answer `poll_failed` "not available yet" until P1.
  P2's tests run them against **test doubles** (`test/p1-doubles.ts`, a view of the app whose `runUntyped` routes
  those ids to small §4.10 implementations over the shipped edit kernel); with `READY.p1` the same tests run against
  P1's real operators.
