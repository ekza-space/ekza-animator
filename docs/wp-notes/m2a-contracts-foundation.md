## Interpretations and decisions

| # | What | Why |
|---|---|---|
| M2A-A0-1 | **Menu-bar Time items without a frame (contract amendment, M2A-SPEC §4.5, §4.9, §5.9).** `time.insertTime.at` is optional and defaults to the active character's current clip frame; Delete Time is its own operator, `time.deleteTime {range?, target?}` (U, A3; stub from A0), which removes the band's frames, or the current frame without a band, as `time.insertTime {at: a − 1, frames: −(b − a + 1), removeKeys: true}`. Time › Insert Frame `{frames: 1}`, Remove Frame `{frames: -1}`, Delete Time `time.deleteTime` (no arguments). | Menu items carry static arguments, so a menu-bar item cannot name the current frame or the band; a fixed `frames: -1` could not express the band rule. The time-slider context menu (A3) may still pass `at`/`range` explicitly. |
| M2A-A0-2 | **Rig › IK/FK is one sub-menu with a group per limb** (Switch to IK/FK, Match FK to IK, Match IK to FK, Match Range to FK/IK for L Leg, R Leg, L Arm, R Arm); Rig › Add Limb IK is a top-level item. The shell labels the sub-menu `IK/FK` (`SUBMENU_LABELS` in `shell/menus.ts`). | Every IK/FK operator requires `limb` (§4.5), and menu arguments are static. |
| M2A-A0-3 | **Stubs that A0 implements anyway:** none. `key.setTarget` and `key.toggleRipple` are stubs like the rest (§3 rule 1), so the status-line key-target items are disabled (tooltip "not available yet") until A2 registers `key.setTarget`; the active item stays enabled. | The toggle polls the operator per item, so it enables itself when A2 lands. |
| M2A-A0-4 | `key.set` (A2's file) poll-fails `target: 'bodyPart'` ("Keying by body part is not available yet") and `breakdown: true` ("Breakdown keys are not available yet") instead of keying the M1 way; `channels: 'attributes'` is accepted by the type and keys no TRS channel. | A silent normal key on `Alt+S` would look like a breakdown that never retimes. The `keyTargetControls` baseline is ready for A2. |
| M2A-A0-5 | **Probe map keys:** `dopeSheet` (A3) and `tween.graph` / `tween.dopeSheet` / `tween.status` (A4, `tweenProbeKey(panel)`); A4's `graph().viewMode` and `screenOfRegionHandle` and A3's `timelineTicks` and `screenOfBand` are **optional members** of the existing graph and timeline probes (the test API answers `'absolute'`, `null` or `[]` without them), so the M1 probes compile unchanged. `graph().buffers` comes from `session.curveBuffers`, not from a probe. **A panel that is not visible reads null** (§4.8): a panel in an inactive dock tab stays mounted and keeps its probe, so the test API answers every Graph Editor read (`graph`, `screenOfKey/Handle/Curve/RegionHandle`) and every Dope Sheet read (`dopeSheet`, `screenOfDopeKey/Region`) with null while that probe's `canvasRect` has no area, and `screenOfTween`/`tweenTarget` of the `graph`/`dopeSheet` bar follow their panel (the status-line bar is always visible). | "keyed by the bar's panel" with the registry's one-probe-per-key semantics; additive for the M1 probe owners; one place for the visibility rule instead of one per probe owner. |
| M2A-A0-6 | **Test API reads flush the scheduler first** (`app.flushScheduled()` in `state`, `counts`, `characters`, `controls`, `clips`, `curves`, `curveValue`, `channelValues`, `overrides`, `boneWorld`, `attrs`, `controlWorld`, `curveSlope`, `limbs`, `limbPivots` and every probe-backed read: panes, cameras, screen positions, panel states). Frame loops call it first: the GL host and fallback scheduler (`frameLoop.ts`) and the dev harness's standalone viewport host. `curveSlope` is exact: at a key the left side is the end slope of the span before it and the right side the start slope of the span after it (from `segmentControlPoints`); outside the range the infinity decides. `flushAutosave()` rejects while `file.autosaveNow` poll-fails (A5). | Coalesced gesture updates (M-1) must not make a probe read stale state between a pointer move and its frame. |
| M2A-A0-7 | **`scheduleBeforeFrame` details:** a later task with the same key replaces the pending one and keeps its place in the order; tasks scheduled during a flush run in the same flush (bounded at 10,000); a throwing task does not stop the others, the first error is rethrown after the flush. "Without a frame requester" means before the host calls `setFrameRequester` (Node, the test kit). `KeyEditGesture.commit` drops a pending update; `beginChannelEditGesture.commit` applies its pending update first (its `commit()` takes no final edit). | One rule for the frame loop, pointerup and tests. |
| M2A-A0-8 | **Attribute slots repair, never reject:** a non-object `AttrDef` gets no slot; a non-finite default reads 0. `writeAttr` ignores unknown attributes and non-finite values; `readAttr` answers `undefined` for unknown controls or attributes. Overrides and `writeControlChannels` write `'@name'` channels through a per-program table (control → `'@name'` → slot, built once from `attrSlots`), so the per-frame override path builds no key strings (MVP-SPEC §3 rule 7); `attrChannelSlot` uses the same table. | MVP-SPEC §3 rule 6 (repair, never reject). |
| M2A-A0-9 | **A `compile` that throws** marks the scheduled op `skipped` (`ScheduledRigOp.skipped`) and warns `unsupported-op`; the op stays scheduled. rig exports `isRigOpSkipped(program, id)` (additive; `LimbDesc` stays verbatim), the kernel binds it as `KernelDeps.rig.isRigOpSkipped` (absent in the naive kit), and `evaluation.ikFk` answers 0 for a limb whose `ik2` op is skipped (§5.4 rule 4), so the test API's `limbs()` and A2's visibility rules read such a limb as FK. The kernel reuses one run context object per program (no allocation per frame). | §4.3 "a throw disables the op for this program (it is skipped at run time and warns)"; §5.4 rule 4 "stays in `limbs` with `ikFk` read as 0". |
| M2A-A0-10 | `sampler/cache.ts` (A4's file after A0) got the minimal attribute-sampling change (a plan entry's `attr` slot and its `AttrDef` default); `insertKeyOnCurve` uses `channelDefaultOf` for key-less attribute curves. | §5.1 rule 3 sampling is A0's; the sampler lives in that file. A4 rebases on it. |
| M2A-A0-11 | **`ensureCurve` is the shared curve-creation helper** of §5.23: on a loop clip every curve it creates by keying or static values gets `cycle` infinities; existing curves are never rewritten. Imports keep `constant` (they create curves through `workflows/records.ts`). **The rotate-order conversion** (`workflows/rotateOrder.ts`) gives a curve it creates the `pre`/`post` of the control's first existing rotation curve in that layer (rx, ry, rz order), so the three converted curves extrapolate alike and the pose past the last key holds as before (an M1 curve, or one keyed before `loop` was turned on, stays `constant`); the loop rule applies only without such a curve (the converter always has one). The conversion samples between keys with the editor's engine (`deps.curves.engine` through rig `convertRotateOrderKeysWith`), so on cyclic curves it converts the cycle-aware values the editor shows (MVP-SPEC §4.11.5 at every key). | One place for "new curves on loop clips"; a conversion must not change the extrapolation it converts. |
| M2A-A0-12 | **Storage switches:** `ns=<1–64 of [A-Za-z0-9_-]>` makes the e2e editor use localStorage under the prefix `ekza-animator:ns:<ns>:` (preferences and layout persist across a reload of the same URL); `storage=blocked` gives a storage whose every access throws a `SecurityError` (every consumer already guards it). `createBrowserServices`/`createShellServices` take `storageNamespace`, `storageBlocked` and `pointerLock` (exported as `BrowserServicesOptions`); A5 uses the first two for the autosave database, A2 reads `pointerLock` from `shell.params.pointerLock`. | §4.8 URL parameters. |
| M2A-A0-13 | **Layout v1 → v2** runs on the dockview API, not on the serialized JSON: the v1 layout is restored, `addDopeSheetTab` adds the tab to the Graph Editor's group (or a new bottom group), and the result is written under the v2 key; the v1 key is only read. `readStoredLayout` returns `{kind: 'migrate', from: 1}` for it. Without a v2 layout and with an invalid v1 layout the M1 reset notice shows. | The grid tree of a serialized dockview is not something to edit by hand. |

| M2A-A0-18 | **`view.tool` with a built-in tool nobody registered yet poll-fails "not available yet"**: once a panel's tools are registered, an id of that panel's built-in set (`GRAPH_TOOL`, `DOPE_TOOL`) that is not registered — the Graph Editor's M2a `scale` (A4), a Dope Sheet tool (A3) — cancels with `not available yet` (§3 rule 1), so `R` over the Graph Editor says that in the help line; any other id stays `Unknown <panel> tool '<id>'`. Without registered tools (headless) the M1 rule holds: any id for the viewport and the Graph Editor, the `DOPE_TOOL` set for the Dope Sheet. | Accepting `scale` with the M1 tools mounted would switch the Graph Editor to a tool it does not have; the owner's registration enables the chord without touching `view.ts`. |
